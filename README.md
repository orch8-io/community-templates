# Orch8 community templates

Reusable [Orch8](https://github.com/orch8-io/engine) workflow sequences that you can pull with the
`orch8` CLI.

| Template | What it does |
|---|---|
| `onboarding-drip` | Sends a welcome email, then a day-1 email. After two business days it checks activation and nudges inactive users. |
| `payment-dunning` | Retries a failed charge up to three times over about 8 days, emailing the customer between attempts, then suspends the subscription. |
| `rag-ingestion` | Fetches each document, embeds it, and stores it in tenant-scoped semantic memory. |
| `approval-chain` | Asks a manager to approve, adds a finance approval above a threshold, then posts the decision to a callback URL. |
| `webhook-fan-out` | Delivers one event to several webhooks in parallel. One subscriber is best-effort, so its failure doesn't fail the run. |

## Use

`catalog.json` uses the format that `orch8 templates --catalog-url` reads. It needs
an `orch8` CLI new enough to have `--catalog-url`, which is newer than 0.7.1.

```bash
CATALOG=https://raw.githubusercontent.com/orch8-io/community-templates/main/catalog.json  # pending: repo not yet published
orch8 templates list --catalog-url "$CATALOG"
orch8 templates pull payment-dunning --catalog-url "$CATALOG" --out payment-dunning.json
# or: export ORCH8_TEMPLATE_CATALOG_URL="$CATALOG"
```

Each `templates/<name>/template.json` file lists:

- the handlers the template uses
- the external workers it needs
- the context fields it expects
- any other prerequisites (`requires`)

Read `template.json` and `sequence.json` before you deploy a template.

## Layout

```
templates/<name>/sequence.json   the sequence (authoring format; no id/version/created_at)
templates/<name>/template.json   metadata + validation context and mocks
catalog.json                     generated by scripts/build-catalog.mjs (do not edit by hand)
scripts/validate.sh              static checks + engine dry-run of every template + catalog freshness
```
